# Qwen3-ASR 重叠窗口与稳定前缀实现方案

日期：2026-09-13

状态：方案已落地；按要求仅完成静态分析，未运行测试或模型。

## 目标

解决 Qwen3-ASR 段式识别中偶发的：

- 句首或句尾漏字；
- 音频刚好落在 2 秒边界时被截断；
- 每个识别段都被当成 final，导致断句过密；
- 重叠识别后出现重复文字；
- 长句超过单窗口后无法连续显示。

本方案只描述实现设计，暂不修改代码。

## 当前行为与问题来源

当前 `Qwen3AsrEngine` 的行为是：

1. `feed()` 持续累积音频；
2. 缓冲区达到 `qwen3_asr_segment_seconds`（默认 2 秒）时立即识别；
3. `_infer_segment()` 清空整个音频缓冲区；
4. 每次识别结果都以 `is_final=True` 发给 UI；
5. 仅在缓冲区超过约 0.5 秒且检测到约 300 ms 静音时提前识别。

这会造成两个独立问题：

- **边界问题**：正在说的词可能正好跨越 2 秒边界，前后两个窗口都只拿到半个词；
- **定稿问题**：2 秒只是识别批次长度，不代表一句话结束，但当前代码把它当成了句子结束。

另外，`soundcard` 的 `data discontinuity in recording` 和采集队列满后丢块，会直接造成音频缺口。这类问题不能仅靠文本后处理完全修复，应与本方案分开监控。

## 推荐组合

推荐同时采用以下四项：

| 机制 | 推荐值 | 职责 |
| --- | ---: | --- |
| 识别 cadence | 约 2.0 秒 | 控制识别调用频率 |
| 音频重叠尾部 | 400 ms，允许 300~500 ms | 保留边界上下文，避免切掉词 |
| 静音终点 | 连续 450~600 ms | 判断当前句子可以定稿 |
| 最大未定稿窗口 | 6 秒左右 | 防止长时间无标点、无静音时无限增长 |

关键原则：

> 2 秒只表示“重新识别一次”，不再表示“句子结束”。

识别 cadence 触发 `partial`，静音或可靠的句末信号才触发 `final`。

## 音频窗口设计

### 正常连续识别

将当前句子的音频保存在未定稿缓冲区中。每次达到 cadence 时：

1. 不清空整个缓冲区；
2. 保留前一次识别所需的上下文；
3. 下一次识别时至少带上 400 ms 的音频重叠；
4. 用最新识别结果覆盖 UI 中的 partial 文本。

推荐的逻辑模型：

```text
输入流:       |------ chunk ------|------ chunk ------|------ chunk ------|
识别窗口:     |========== 2.0 s ==========|
下一窗口:              |========== 2.0 s ==========|
重叠部分:              |---- 0.4 s ----|
```

实现上不应简单地把相邻识别结果拼接起来，因为重叠区域会导致同一词被识别两次。partial 阶段应优先使用“当前窗口的完整假设”覆盖旧 partial，而不是追加 delta。

### 最大窗口

当未定稿音频超过最大窗口时，不能无条件丢弃前半段。建议执行以下顺序：

1. 从最近几次识别结果中计算稳定前缀；
2. 只选择位于安全边界的稳定前缀进行定稿；
3. 将该前缀从 UI 的 partial 区域提交为 final；
4. 按稳定前缀占当前假设的比例估算音频切点，保留切点前约 400 ms 的上下文以及全部未定稿后缀音频；
5. 下一窗口识别后，对已定稿文本和新结果做文本重叠消除。

如果没有足够稳定的前缀，允许临时超过目标最大窗口，直到出现静音、句末标点或更可靠的稳定结果。这样比在词中间强制切断更安全。

## 稳定前缀算法

### 状态

Qwen 引擎建议增加以下状态：

```text
_audio_buf                 当前未定稿音频
_last_hypotheses           最近若干次完整识别结果
_stable_prefix             已在连续结果中保持不变的文本前缀
_committed_tail             最近一次 final 的末尾文本，用于去重
_silence_run               连续静音样本数
_last_infer_time            最近一次识别时间或累计样本位置
```

### 稳定判断

每次识别都要求模型返回“当前窗口的完整文本假设”，不要只返回新增 delta。对最近 2~3 次结果：

1. 先做轻量归一化：去除首尾空白，统一明显的重复空格；
2. 求这些结果的最长公共前缀；
3. 只把“连续多次相同，且位于安全边界”的前缀视为稳定；
4. 中文优先要求前缀在句末标点处结束；
5. 英文或混合语言优先要求前缀在空格、标点或完整词边界结束；
6. 没有安全边界时，不要为了满足最大窗口而按字符硬切。

伪代码：

```text
hypothesis = recognize(current_window)
history.append(hypothesis)

common = longest_common_prefix(history[-3:])
safe = trim_to_sentence_or_word_boundary(common)

if endpoint_detected:
    emit(final_text=hypothesis)
elif safe is sufficiently long and max_window_reached:
    emit(final_text=safe)
    continue_with_suffix_after_dedup()
else:
    emit(partial_text=hypothesis)
```

稳定前缀不是“模型已经确认句子结束”的证明。它只表示这段文字在连续识别结果中没有继续变化，因此适合在必须滚动窗口时提前提交。

## 终点判定

Qwen3-ASR Transformers 接口当前没有可靠的句子结束布尔值，因此采用多信号判定：

### 强信号

- 连续静音达到 450~600 ms；
- `stop()`；
- 采集流或 pipeline 明确结束。

### 辅助信号

- 最新文本以 `。！？!?；;` 等句末标点结束；
- 句末标点在连续两次 partial 中保持不变；
- 标点后持续出现短静音。

推荐规则：

```text
连续静音 >= 500 ms
    -> final

句末标点稳定出现 + 连续静音 >= 250~300 ms
    -> final

仅因为 cadence 到期
    -> partial，不 final
```

不能仅凭模型是否输出句号就立即 final，因为 ASR 可能提前补标点，也可能在下一次识别中撤回标点。

## 文本输出契约

### partial

每次 cadence 识别成功后：

```python
self.on_result(text, is_final=False, source=self.source, spk_id=None)
```

其中 `text` 应是当前未定稿区域的完整假设，不是增量片段。

这与当前 `SubtitlePanel` 的设计兼容：同一 `(source, spk_id)` 的 partial 会覆盖旧的 interim 区间，允许模型跨窗口纠错。

### final

只有下列情况才发送：

```python
self.on_result(text, is_final=True, source=self.source, spk_id=None)
```

- 静音终点成立；
- `stop()` 刷新剩余内容；
- 最大窗口触发且已经找到安全稳定前缀。

当前 `app.py` 只把 `is_final=True` 的文本交给翻译线程，因此 partial 不会反复触发翻译。这一点应保持不变。

## 重叠文本去重

重叠窗口可能导致新一轮识别以最近一次 final 的尾部开头。提交 final 或切换最大窗口时，需要做文本重叠消除。

建议顺序：

1. 对旧尾部和新文本做同样的轻量归一化；
2. 查找“旧文本后缀 = 新文本前缀”的最长匹配；
3. 只在匹配长度达到最低阈值时删除重复前缀；
4. 中文可按字符匹配；
5. 英文、数字和混合文本必须尽量在空格或标点边界去重，避免把 `there` 和 `the` 误判成重叠；
6. 去重结果为空时，不发送空 final。

建议不要使用任意长度的短前缀去重。单字符匹配在中文中也可能误删真实重复词，在英文中风险更高。

## UI 与断句配合

当前 UI 已有以下有利条件：

- `is_final=False` 会覆盖当前 interim；
- `is_final=True` 会提交永久文本；
- partial 不经过最终的 `LineBreaker` 分段；
- final 才会按句末标点和引擎边界换行。

因此 Qwen 引擎侧最重要的调整是：

1. cadence 结果改为 partial；
2. 静音或可靠终点结果才为 final；
3. final 文本必须是完整、去重后的提交内容；
4. 不要把每个 2 秒窗口直接当成一行字幕。

否则即使 ASR 文字本身正确，UI 也会因为每段 `final` 自动换行而产生“断句异常”。

## 采集缺口的独立风险

方案不能修复已经丢失的 PCM。静态检查发现：

- `SystemAudioCapture` 和 `MicrophoneCapture` 的队列容量为 64；
- 推理线程处理不过来时，采集线程的 `queue.put(..., timeout=1)` 失败后直接丢弃当前块；
- 每块通常约 100 ms，因此队列满时可能连续丢失多个音频块；
- `data discontinuity in recording` 也表示采集流本身出现了不连续。

重叠窗口会增加 Qwen 推理量。如果 4-bit 模式下推理速度已经低于实时速度，重叠可能使队列更容易满，反而加重漏字。因此实现时应同时记录：

```text
采集块总数
丢弃块数
队列峰值
推理耗时
音频累计时长
```

实现中应对队列丢块和慢于 cadence 的 Qwen 推理做节流告警，并在停止时输出汇总。如果推理吞吐不足，应优先降低重叠到 300 ms、降低 cadence 频率，或扩大队列并采用有界的背压策略，而不是无限增加窗口。

## 建议的实现顺序

### 第一阶段：改变定稿语义

1. 保留约 2 秒 cadence；
2. cadence 结果发送 partial；
3. 静音达到约 500 ms 时发送 final；
4. `stop()` 继续 final 刷新；
5. 不改变 UI 和翻译契约。

这一阶段即可消除“每 2 秒强制断句”的主要问题。

### 第二阶段：加入重叠窗口

1. 引入 300~500 ms 音频尾部重叠；
2. partial 始终发送当前窗口完整文本；
3. final 前保留完整当前句音频；
4. 确认不因重叠直接拼接重复文本。

### 第三阶段：加入稳定前缀与最大窗口

1. 保存最近 2~3 次 hypothesis；
2. 计算公共前缀；
3. 仅在安全边界提交稳定前缀；
4. 增加最大窗口保护；
5. 实现跨窗口文本重叠去重。

分阶段实现可以把“断句语义”“边界保护”“超长句滚动”三个问题分开定位。

## 推荐默认参数

```text
qwen3_asr_segment_seconds = 2.0
overlap_seconds            = 0.4
endpoint_silence_seconds   = 0.5
max_window_seconds         = 6.0
stable_history_size        = 3
punctuation_confirmations  = 2
```

参数不应写死在算法中，后续可放入 `AsrConfig`。其中 `overlap_seconds` 和 `max_window_seconds` 需要考虑 4-bit 模式下的实际推理吞吐。

## 验收标准

静态设计对应的行为标准如下：

- 2 秒到期不会自动产生 final；
- 句中跨越识别窗口时，partial 不应截断已识别前缀；
- 句尾词位于窗口边界时，重叠窗口仍能看到完整上下文；
- 连续 partial 不会在 UI 中累积重复；
- 静音约 500 ms 后才提交 final；
- final 不会重复触发翻译；
- 长句达到最大窗口时，只提交稳定且位于安全边界的前缀；
- 采集发生丢块时，日志能够区分“音频缺口”与“ASR 边界误差”；
- 4-bit 推理吞吐不足时，不会因为重叠窗口无界增加计算量。
